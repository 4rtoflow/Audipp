# yt-dlpサーバー中継と利用者選択による端末保存

| 項目 | 内容 |
|---|---|
| 日付・版 | 2026-10-28 / 1.0.0-draft |
| 根拠 | 利用者がサーバー経由方式を承認し、「端末保存を望む場合は保存、望まない場合はストリーミング」と指定 |
| 対象 | YouTube / YouTube Music。別サービスの保存許可を一括変更しない |
| 採用 | Debian上のyt-dlpで音声を解決/取得し、認証済みHTTPSでAudippへ中継。端末でデコード/DSP/出力、希望時だけ端末フォルダへ保存 |
| 後段候補 | 端末へのyt-dlp内蔵。現在の完成条件ではなく、サーバー不要の取得が必要になった段階で別途検討 |
| 状態 | 方式・動作の決定。サーバー配備、実サービス取得、端末動作は未検証 |

## 利用者が観測する動作

既定は「保存しない」。Audippは再生要求時に保存希望を表示し、利用者が変更した設定を次回も使う場合は明示的に保存する。保存を望まない場合はストリーミングし、共有フォルダへ音源を作らない。再生に必要な一時キャッシュは容量制限と期限で削除し、保存曲一覧へ登録しない。

「端末に保存」を選ぶと、Audippは保存先と保存可否を確認してから取得ジョブを作る。既存の保存先権限があればそのフォルダを表示し、なければシステムのフォルダ選択を開く。取消・権限拒否・保存用途不許可なら保存を始めず、「保存せず再生」「保存先を選び直す」「取消」を提示する。保存失敗を隠して保存済みやストリーミング成功扱いにしない。

取得した音声は再生と保存で共用できる。保存を選んでも全体取得完了を再生開始条件にせず、対応する形式/経路では先に再生できる。画面には再生状態と保存状態を別表示する。再生Stopは明示した保存ジョブの取消と別操作にし、保存取消で進行中の再生を自動停止しない。アプリ/OSが処理を終了した場合は完了と表示せず、再開可能か再検査する。

保存ファイルの削除は本人操作とし、キャッシュ消去やログアウトだけで端末の指定フォルダに保存済みの音源を削除しない。利用者の音源利用権・提供元条件を尊重し、保存できる権限がない音源を取得/永続化する経路には切り替えない。保存を希望すること自体は提供元の保存許可ではない。

## 取得・再生の責務

```text
Audipp -> 私用HTTPS APIへ音源ID/保存希望
             -> yt-dlp workerで音声専用形式を解決
             -> workerと同じ側で音声取得
             -> 中継/一時キャッシュ
             -> AudippのPlayerへ配信 -> decode/DSP/出力
                                     -> 保存希望時だけ選択URIへ書込
```

yt-dlpは音源解決/取得を担当し、再生状態やDAC出力の所有者にはならない。サーバーは原則再圧縮せず音声のみを中継し、映像を含む形式へ切り替えない。必要なコンテナー処理とcodecを記録し、非可逆音源をFLACへ変換して音質向上と表示しない。サーバーからPCMを送り続ける構成は初期方式にしない。

上流URLだけを端末へ返す方式は初期経路にしない。URL解決と実データ取得の接続元/認証ヘッダーをサーバー側で合わせ、Audippには上流Cookie/URL/秘密を渡さない。端末へ渡すのは本人が読める中継session ID、codec/container、曲長/サイズ/seek能力の既知値。未知値はNULL/不明とする。

最初の接続試験は認証不要で利用条件を満たす試験音源から行う。YouTube Musicを含む本人認証が必要なケースは別試験とし、全員でひとつのCookieを共有しない。ユーザー別のサーバー側認証情報の預託・保存/撤回・削除方法は別途設計し、本人の明示操作なしに端末Cookieをアップロードしない。認証が未設定ならAUTH_REQUIREDで止め、ログイン必須音源を認証不要と偽らない。

## 私用APIとジョブ

| 操作 | 入力/結果 | 制約 |
|---|---|---|
| POST /v1/youtube/sessions | source種別、音源ID、saveRequested、冪等request_id -> session_id/状態 | callerを本人として検証。任意URL/コマンド/出力pathは受け付けない |
| GET /v1/youtube/sessions/{id} | 状態、既知の形式/長さ/seek、エラー/再試行可否 | user_idとsession所有者を毎回照合。別ユーザーへ列挙しない |
| GET /v1/youtube/sessions/{id}/audio | 音声body、対応時のみRange | 上流秘密をredirectや応答へ出さない。未対応Rangeを206と表示しない |
| DELETE /v1/youtube/sessions/{id} | 取得利用の終了/取消 | playbackと保存の利用参照がなくなった時にworkerを停止し、一時データを削除 |

端末側は保存ジョブID、source ID、session ID、選択先URI、受信bytes、取得世代、既知の形式/長さ、状態、エラーを永続化する。URIは端末だけに置き、サーバーや同期へ送らない。sessionが失効したときは同じ本人・音源から作り直すが、転送中の内容が同じか不明なまま異なるbyte列を結合しない。

server sessionはCREATED/RESOLVING/READY/TRANSFERRING/FAILED/CANCELLED/EXPIREDを区別する。端末保存はAWAITING_DESTINATION/QUEUED/TRANSFERRING/VERIFYING/COMPLETED/FAILED/CANCELLEDとし、COMPLETEDは端末で検査と確定が済んだ後だけ。API受付成功やサーバー取得完了だけで保存済みにしない。

## シーク・中断・保存確定

シークは上流Range/segment対応と取得済み領域を検査する。未取得位置へ移動する場合は、その位置のデータを取得し、音源上の時刻を確認してから再開する。できない場合はseek不可/再試行を表示し、単純なpipe転送を完全なseek対応としない。URL失効は同じ音源の再解決と媒体の同一性検査を経由する。

保存は元の音声containerを基本とし、長さ既知なら受信長、完了通知、demux/再読込、保存結果を検査して確定する。曲名・時間・source IDとファイル名を別管理し、パストラバーサル・衝突を拒否する。既存ファイルは無断上書きせず、新規名か本人の選択を使う。raw pathではなくSAF URIへContentResolverで書くため、yt-dlpへcontent URIを通常の出力pathとして渡さない。

一時ファイル/未完了名とjournalを使い、検証後に確定名へ移す。providerのrename/原子置換を仮定せず、非対応時は新規コピーを検査してから完了記録を付ける。未完成ファイルをライブラリへ登録しない。容量不足、SD抜去、権限失効、転送中断はFAILEDとし、元ファイルを破壊せず再選択/再試行を提示する。再開時は同じ媒体・offsetを検査し、同一性を確認できなければ未完了分を作り直す。取得完了・検査成功後に保存Variantを登録し、元のProvider IDと関連付ける。別曲との自動同一化はしない。

## 実行環境・資源・秘密

サーバー側でyt-dlp・Python・JS runtime/ejsを管理し、導入時に互換性を確認して版を固定する。更新は既知音源の解決/再生/seek回帰試験後に適用する。現在のAPI23をyt-dlpラッパーのために引き上げず、他のAndroid依存の下限検査は継続する。端末内蔵のAPI24問題は後段候補の課題へ移す。

workerはアプリAPI/DBと分離し、非root・専用一時領域で動かす。shellへ利用者入力を連結せず、環境のyt-dlp config・任意plugin/execオプションを読み込ませない。YouTube/YouTube Musicの検査済みID/hostだけを受付け、上流redirect/DNSも検査してlocalhost/私用ネットワーク/メタデータ等への取得を拒否する。コマンド引数・URL・Cookieを通常ログへ出さない。利用者別の認証/媒体データを混ぜない。

同時取得は初期値全体2件/本人1件、待ち行列8件、未使用sessionは10分で失効、一時キャッシュは合計1 GiB以内/最終利用終了後30分以内に削除する。稼働中のデータを黙って切捨てず、上限時は待機/容量エラーを表示する。値は私用負荷試験で改訂する。端末の受信bufferも上限を持ち、serverの取得進行で端末メモリを無制限に増やさない。server停止時も端末に保存済みの音源/ローカルライブラリは再生できる。

## 導入順と試験

1. 私用サーバー側の音声解決/中継と、端末の逐次再生・seek・停止/切断・URL失効を検証する。
2. 同じ取得基盤へ「端末に保存」を追加し、保存希望なし/ありの両方、保存先選択/取消、容量/権限/SD/再起動・中断再開・検査/確定を検証する。
3. 両モードが成立してからYouTube系機能の完成と判定する。端末内蔵をその条件に追加しない。

TEST-YTDLP-01はサーバー中継、認証/所有者、seek/失効、資源上限、server停止と既存ローカル再生の継続を確認する。TEST-SAVE-01は本人の保存選択だけでファイルを作ること、一時cacheと確定音源の分離、失敗復旧と完了後のオフライン再生を確認する。試験対象はGalaxy S25/FiiO M21を主要、Galaxy S20を追加とする。既存TEST-PROV-01/RESEARCH-01/QUEUE-01/SEC-01にも接続する。
