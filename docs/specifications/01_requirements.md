## 0. 本書の位置づけと「完成」の定義

本書は、まず開発者と招待した個人が日常的に使える完成版Androidアプリの要求を定める。2026-10-28の利用者指示により、個人間利用での完成と、不特定多数への一般公開を別段階にする。一般公開の準備が整うまで音楽アプリの完成を保留する扱いは廃止する。

- **現在の完成目標（C/RB）**：原典のAndroid向け機能を、個人間の音源再生・同期・招待した相手との共有に使える状態にする。全サービス直接再生、日英UI、音声上限、主要端末等の回答済み条件は維持する。段階的な実装中の版を完成版とは呼ばない。
- **完成後の発展（PUBLIC）**：一般向け自己登録、メール送信による確認・復旧、不特定多数への機器情報公開とその審査運用、ストア申請・掲載、公開名義・最終配布経路、問い合わせ/脆弱性窓口・常設サポート、公開用の規約・プライバシー文書と年齢区分。元の要件IDを消さず適用段階を分ける。
- **現在も必要な条件**：本人ごとの認証・招待相手の権限・削除・秘密保護・通信保護・バックアップ復旧・適法な音源/API利用・依存ライセンス。個人間利用を根拠にサービス側の条件や機器能力を無視しない。
- **適用条件**：Native DSDの対応機器、取得可能な機器情報、PCMを扱えない外部音源などの条件を保持し、成立する組合せで試験する。未達の必須機能を、理由表示だけで達成扱いにしない。
- **現状**：PoCは初期画面とGradle環境。仕様の決定、設計レビュー、実装、実機合格、一般公開準備は別の状態として記録する。

### 要求状態の凡例

| 記号 | 意味 |
|---|---|
| `CONFIRMED` | ユーザーが既に決定した製品方針 |
| `PROPOSED` | 本書が推奨する完成版の実装・動作要求、正式承認待ち |
| `BLOCKED` | 必須範囲は確定しているが、権利・能力・予算・設計・実装・検証の不足により該当機能の完成判定を止めている状態 |
| `EXCLUDED` | 現段階の対象OS・実装対象外 |

本書の表で `C/RB` は個人間利用版の完成に必須を示す（RBの意味を本改訂で更新）。機能の採否はCONFIRMEDであり、具体的な動作・閾値・方式は個別に確定する。従来のG/Oによる個人間利用版からの除外を廃止する。EXCLUDEDは原典§13が初期対象外とするOSにのみ使用する。

原典の全箇条書きから要求ID・設計・試験への対応は[個人間利用版機能対応表](05_feature_coverage.md)で管理し、Q-01〜13の回答と、残るR調査・P具体化は[判断事項・回答シート](06_decisions.md)へ集約する。原典§14の調査・検証も個人間利用版前の必須作業とし、調査を終えたことと製品機能が使えることを分ける。

## 1. プロダクト要求（PRD）

### 1.1 解決する課題と提供価値

- **高音質・詳細制御**：ローカル音源、PCM/DSD、DSP、出力機器の能力と実際の経路を利用者が理解し、サポートされた範囲で精密に制御する。
- **統合音楽体験**：端末内音源と複数音楽サービス・ネットワーク音源を可能な範囲で共通ライブラリ／プレイリスト／キューへ統合する。操作できない外部プレーヤーを「同一エンジンでシームレス再生」と誤表示しない。
- 上記**二つの価値は同等に重視する（CONFIRMED）**。短期工程の順序は戦略的価値の優劣を意味しない。

### 1.2 対象・非対象

| 項目 | 方針 |
|---|---|
| 対象端末 | Androidスマートフォン、Android搭載DAP（CONFIRMED） |
| 初期検証 | 現在のPoCの延長としてローカル音源再生から開始（CONFIRMED） |
| 公開 | 現在は招待した個人間での利用を完成目標とし、一般公開は完成後の発展（CONFIRMED） |
| その他OS | iOS/iPadOSはAndroid完成・安定後に余力で検討。Windows/Linux/macOSは計画外（既存方針） |
| 対象利用者 | ローカル音源利用者、オーディオ愛好家、複数ストリーミング利用者、DAP利用者 |
| 配布・料金 | 個人間のインストール・更新試験は署名APKを使う。無料・広告なし。一般向けGoogle Play/APK配布の選択と公開名義は完成後 |
| 地域・言語・年齢 | 現状日本で公開、日本語・英語UIを必須。特定年齢を製品ターゲットに指定しない。ストア区分・サービス制限は別途確認 |
| 必須対応・主要検証端末 | Galaxy S25（Android 16）、FiiO M21（OS版未確認）。追加検証端末としてGalaxy S20（OS版未確認）も利用可能。DACはiFi audio ZEN DAC V2、水月雨ECHO-B/ECHO-Aを利用可能と想定。各firmware・実能力・測定結果は未確認 |

### 1.3 ユーザージャーニー

`初回起動 → ローカルライブラリ登録／外部サービス連携 → 統合検索 → ソースを選択 → キュー編集 → 再生／外部委譲 → 出力先・プロファイル選択 → 信号経路・Visualizer表示 → 履歴／推薦 → 同期／共有（同意した場合）`

端末音源の再生と基本ライブラリ閲覧は**アカウントなし・オフラインで利用可能**とする。

### 1.4 受益・成功指標（個人間利用版の合格基準）

| 指標 | 必須となる評価内容 | 承認状態 |
|---|---|---|
| Core Playback | ローカル再生、キュー、バックグラウンド、切断復帰、エラー回復が対応端末で成立 | 条件は本書で提案 |
| Audio Trust | ロスレスPCM、原典のPCM/DSD各方式、Bit-perfect、ReplayGain/R128/PEQ/FIR/Crossfeed等すべてを対応環境で実証する。表示根拠を分離し、原典の適用条件を試験へ記録する | **全方式の個人間利用版必須はCONFIRMED**。機器能力は未実測。処理方式/初期測定基準は09で選定 |
| Integration | Qobuz、Amazon Music、Spotify、SoundCloud、Apple Music、YouTubeとYouTube Musicのすべてで直接再生と混在キューを満たす。カタログ検索は技術・許諾上可能なら実装する。遠隔操作・外部遷移で直接再生を代替しない | **全サービス直接再生はCONFIRMED（Q-01）**。実装手段と用途別許諾はR-06で確認 |
| Quality | 無クラッシュ率、ANR、音切れ、操作応答、電力、アクセシビリティ | 初期基準は09のQLT-01〜14。達成は実機試験で判定 |
| Completion / PUBLIC | 個人間版は音源/API条件・秘密保護・依存ライセンス・署名更新・復旧を満たす。ストア審査/常設窓口は完成後 | 段階ごとに判定 |

## 3. 機能要件（個人間利用版の機能を必須）

以下は実装・テストを追跡する**安定ID**。各行はユーザーが観測できる結果（WHAT）を記す。HOWは設計書を参照する。

### 3.1 ソース、ローカルライブラリ、メタデータ

| ID | 区分 | 要求仕様・判定観点 |
|---|---|---|
| FR-SRC-01 | C/RB | ローカルファイル、サービス楽曲、ネットワーク音源を共通のソース識別子で表示し、提供元を常時特定できる。 |
| FR-SRC-02 | C/RB | ローカル音源をシステムの許可UIから選択し、許可されたフォルダ／音源をインデックス化、更新、削除できる。拒否・失効時に復旧可能である。 |
| FR-SRC-03 | C/RB | 曲、アルバム、アーティスト、ジャンル、年、音源形式を検索・ソート・絞込みできる。タグ欠損を扱う。 |
| FR-SRC-04 | C/RB | MP3、AAC/M4A、WAV、FLAC等の対応一覧と制約を表示し、形式別・端末別の試験結果を公開する。DSD等の特殊形式はFR-AUD-05に従う。 |
| FR-SRC-05 | C/RB | タグ、フォルダ、トラック／ディスク番号からアルバムを構築し、アルバムアートを扱う。確定できる組を自動分類し、曖昧な候補は修正・分割できる。取得できない属性は「不明」と表示する。高解像度画像でメモリ枯渇させない。 |
| FR-SRC-06 | C/RB | MusicBrainz/AcoustID等との照合、タグ修正、アルバムアート取得・差替を提供する。元ファイルを変更する場合は明示同意を要する。 |
| FR-SRC-07 | C/RB | 重複、異なる音質版、同一曲・異マスターを関連付け、誤同定時に解除できる。 |
| FR-SRC-08 | C/RB | 外部サービス別に認証・再生方式・メタデータ取得範囲・利用可能機能を明示し、権限外の音源は再生しない。検索、混在表示・キュー、履歴保存、統計、推薦、Scrobble、同期、PCM加工・解析は用途別に許諾を確認し、未確認・不許可の処理へデータを渡さない。 |
| FR-SRC-09 | C/RB | Qobuz、Amazon Music、Spotify、SoundCloud、Apple Music、YouTubeとYouTube MusicのすべてでAudippによる直接再生を実装・検証する。提供元ごとに用途別許諾を確認する。REMOTE/HANDOFFは補助操作に限り、直接再生の達成とは扱わない。 |
| FR-SRC-10 | C/RB | 技術・許諾上可能なサービスについてカタログ検索・横断検索と関連付けを実装する。検索不可のサービスは理由を表示し、直接再生まで省略しない。ローカル検索は引き続き必須。 |
| FR-SRC-11 | C/RB | YouTubeとYouTube Musicはyt-dlpを用いた音声のみの逐次再生を必須とし、映像再生・動画UIを設けない。事前全体保存を必須にせず、URL失効、シーク、認証、通信断を処理する。技術検証、利用条件、音源の権利、配布可否を別々に記録する。 |

### 3.2 再生・統合キュー・プレイリスト

| ID | 区分 | 要求仕様・判定観点 |
|---|---|---|
| FR-PLY-01 | C/RB | 再生・一時停止・再開・停止・前後曲・シーク・リピート・シャッフルを提供する。シーク不可時は無効化する。 |
| FR-PLY-02 | C/RB | バックグラウンド、通知、ロック画面、メディアボタンから正しい再生状態を操作できる。 |
| FR-PLY-03 | C/RB | 音声フォーカス、着信、外部出力切断、アプリ復帰、OSによる停止で安全な状態遷移を行う。 |
| FR-PLY-04 | C/RB | キューの追加・削除・順序変更・全消去・重複許容・永続化・復元を提供する。楽曲リンク切れにも耐える。 |
| FR-PLY-05 | C/RB | プレイリストを作成・名前変更・並べ替え・削除できる。キューとプレイリストを分離する。 |

| FR-PLY-08 | C/RB | 同一出力エンジンで連続再生可能な対象ソース／形式ではギャップレスを提供する。外部アプリ間での完全なギャップレスは保証しない。 |
| FR-PLY-09 | C/RB | キュー内のソース種別・音声形式・推定時間・外部委譲の有無・再生不可理由を表示する。 |

### 3.3 高音質エンジン、PCM/DSD、DSP

| ID | 区分 | 要求仕様・判定観点 |
|---|---|---|
| FR-AUD-01 | C/RB | 現在の音源コーデック、元サンプルレート／ビット深度、デコード状態、要求した出力、OS申告経路、観測経路を**出典別**に表示する。 |
| FR-AUD-02 | C/RB | Android標準再生経路を標準で提供し、サポートされない高度な出力設定は選択不能にする。 |
| FR-AUD-03 | C/RB | 対応機器で標準経路、Direct／Bit-perfect経路、検証済み独自USBバックエンドを選択でき、それぞれの能力と制約を表示する。成立確認できない環境ではBit-perfect「検証済み」と表示しない。 |
| FR-AUD-04 | C/RB | PCMは384 kHz・32-bitを上限とし、上限超や出力先非対応の形式は対応形式へ変換して正常再生する。2倍・4倍/Hz指定変換、NOS相当バイパス、複数リサンプラーと品質・Linear/Minimum/Apodizing等のフィルター選択を提供する。変換内容を表示し、変換経路をBit-perfectとしない。 |
| FR-AUD-05 | C/RB | DSD上限はDSD256とし、Native DSD、DoP、DSD→PCM、PCM→DSDを対応経路で提供する。方式・レート・変換を表示する。通常2ch、最大5.1chは試験機能とし、対応出力とチャンネル配置を検査する。非対応のチャンネル構成は説明付きでステレオへダウンミックスする。 |
| FR-AUD-06 | C/RB | ReplayGain（Track/Album/Preamp/クリップ防止）、R128/LUFS正規化、パラメトリックEQ、FIR/Convolution、Crossfeed、左右ゲイン／入替／モノラル化を提供する。 |
| FR-AUD-07 | C/RB | DSPの適用順序・Preamp・Headroom・クリッピング検出／防止を明示し、DSPの加工とBit-perfectの排他関係を強制する。 |
| FR-AUD-08 | C/RB | 音量設定は聴覚安全性を優先し、出力先変更で突然大音量にしない。物理ゲイン等の制御不能値は「手動設定」と明示する。 |
| FR-AUD-09 | C/RB | フィルターやバッファ等の変更を再生中に安全に反映し、適用不可／再初期化要の結果を表示する。 |
| FR-AUD-10 | C/RB | 据置向け高音質設定と低負荷なポータブル設定をプリセットとして切り替え、変更するDSP・リサンプル・可視化品質を適用前に確認できる。安全音量・許諾・機器能力を上書きしない。 |

## 7. 非目標／禁止する誤表示

- 許諾のないストリーム取得、DRM回避、コーデック・SDKライセンス違反。
- サンプルレート表示だけでのBit-perfect断定。
- DSP処理と、同じPCMサンプルがDACまで無変更であるという保証の同時表示。
- 外部アプリが所有するPCMをAudippのDSP／Visualizerで処理したという表示。
- 未対応のストリーミング事業者／DAC／機種での動作保証。
- 端末固有オーディオ制御やアカウント登録を、一般的なローカル再生の必須条件にすること。

## 9. トレーサビリティ規約

- GitHub Issue・PRに少なくとも `FR-xxx` / `NFR-xxx` を記載し、関連する[詳細設計書](03_detailed_design.md)の `DD-xxx` と、`UAT-xx/TEST-xx` をリンクする。
