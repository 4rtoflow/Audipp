## 0. 本書の位置づけと「完成」の定義

本書は**最初のPoC／MVPだけの要求書ではない**。既存のPoCは開発出発点であり、製品構想に掲げた機能群を一般公開可能なアプリとして実現する際の要求、依存条件、受入条件を定める。

- **製品の完成像（Target Product）**：本書に列挙する14領域の機能要求に対し、サポート可能な機能が設計・実装・検証され、依存先の承認が得られた外部連携が組み込まれた姿。
- **初回一般公開（Release Baseline / RB）**：市場公開に必須の一貫したユーザー体験、権利・プライバシー・安全・品質要件を満たす状態。全「条件付き機能」が公開できることまでは保証しないが、対応・非対応・制約を公開前に確定し、機能広告に反映する。
- **現状のPoC（Implementation Baseline）**：Kotlin／Composeの初期画面とGradle環境。再生・USB DAC等は未実装。完成版で使う設計は段階的に追加する。
- **「実装対象」と「提供保証」は別**：構想から機能を消さない。ただしAPI許諾やデバイス能力が得られない機能は、無断に実装・出荷せず、Gateで条件付き・非対応・代替策を確定する。
- **完全な要求確定ではない**：外部サービス契約、公開ストア、サーバー運用予算、対象機種、品質閾値は未決定であり、承認が必要。

### 要求状態の凡例

| 記号 | 意味 |
|---|---|
| `CONFIRMED` | ユーザーが既に決定した製品方針 |
| `PROPOSED` | 本書が推奨する完成版の実装・動作要求、正式承認待ち |
| `GATED` | API権利・OS／DAC能力・採用予算などを確認後に提供範囲を決める要求 |
| `OPTIONAL` | 最終構想には含めるが、初回一般公開までの実装を現時点では確約しない |
| `EXCLUDED` | 現段階の対象OS・実装対象外 |

本書の表で `C`=完成像の要求、`RB`=初回一般公開での提案必須、`G`=条件付き、`O`=完成像の選択実装を示す。**CがRBを意味するわけではない**。RB/G/O区分はプロダクトオーナー未承認の提案である。

## 1. プロダクト要求（PRD）

### 1.1 解決する課題と提供価値

- **高音質・詳細制御**：ローカル音源、PCM/DSD、DSP、出力機器の能力と実際の経路を利用者が理解し、サポートされた範囲で精密に制御する。
- **統合音楽体験**：端末内音源と複数音楽サービス・ネットワーク音源を可能な範囲で共通ライブラリ／プレイリスト／キューへ統合する。操作できない外部プレーヤーを「同一エンジンでシームレス再生」と誤表示しない。
- 上記**二つの価値は同等に重視する（CONFIRMED）**。短期工程の順序は戦略的価値の優劣を意味しない。

### 1.2 対象・非対象

| 項目 | 方針 |
|---|---|
| 対象端末 | Androidスマートフォン、Android搭載DAP（CONFIRMED） |
| 初期検証 | 現在のPoCの延長としてローカル音源再生から開始（CONFIRMED） |
| 公開 | 将来の一般公開を前提に開発（CONFIRMED） |
| その他OS | iOS/iPadOSはAndroid完成・安定後に余力で検討。Windows/Linux/macOSは計画外（既存方針） |
| 対象利用者 | ローカル音源利用者、オーディオ愛好家、複数ストリーミング利用者、DAP利用者 |
| 配布 | Google Playを第一候補として**提案**。ストア・配布地域・年齢・価格モデルは未決定 |

### 1.3 ユーザージャーニー

`初回起動 → ローカルライブラリ登録／外部サービス連携 → 統合検索 → ソースを選択 → キュー編集 → 再生／外部委譲 → 出力先・プロファイル選択 → 信号経路・Visualizer表示 → 履歴／推薦 → 同期／共有（同意した場合）`

端末音源の再生と基本ライブラリ閲覧は**アカウントなし・オフラインで利用可能**とする。

### 1.4 受益・成功指標（公開前に定量値を最終承認）

| 指標 | 必須となる評価内容 | 承認状態 |
|---|---|---|
| Core Playback | ローカル再生、キュー、バックグラウンド、切断復帰、エラー回復が対応端末で成立 | 条件は本書で提案 |
| Audio Trust | フォーマット・経路・Bit-perfectの表示根拠が正確で虚偽がない。**RBではFLACなどのロスレスPCM音源の実機再生**に加えて、**ReplayGain／Parametric EQ／検証済みDirect経路の少なくとも1種類**を実機で提供・評価することを提案 | 原則確定、RBに必要な高度機能の選択は要承認 |
| Integration | 正規の許諾による少なくとも1つの実用的なストリーミング連携が公開版で動作。複数サービス統合を謳う際は2サービス以上の連携を実証 | **RB提案／要承認** |
| Quality | 無クラッシュ率、ANR、音切れ、操作応答、電力、アクセシビリティ | 数値目標を公開前に確定 |
| Release | 法令、利用規約、プライバシー、ライセンス、ストア審査、運用窓口を満たす | 判定必須 |

## 4. 非機能要件（NFR）

**数値は正式要件の提案初期値であり、計測端末・測定手順・公開判定の承認前に無条件の保証にしない。** 測定困難な項目は `TBD + 承認期限` を残す。原則として公開前に閾値を凍結する。

| ID | 分類 | 要求・提案目標 | 測定／合格方法 |
|---|---|---|---|
| NFR-REL-01 | 安定性 | 読込失敗、権限失効、通信切断、再生デバイス切断で未処理クラッシュを発生させない | 障害注入テスト全件合格 |
| NFR-REL-02 | 長時間再生 | **提案**：オフラインのプレイリスト連続再生8時間で再生制御不能・アプリクラッシュ・再現性ある音切れ0件 | 端末×形式×出力別実機測定（実測前は未達） |
| NFR-REL-03 | リカバリ | 強制終了やOS停止後は、直前のキューと進捗を安全に復元可能。自動再生は明示方針に従う | プロセス停止・再起動・権限失効テスト |
| NFR-PERF-01 | 応答性 | UIメインスレッドで重いファイル解析・ネットワークIOを行わない。入力応答のP95提案値：200ms以内（画面描画開始まで） | Macrobenchmark・トレース、端末条件固定 |
| NFR-PERF-02 | 起動／再生 | Cold Start、選曲→音声開始、シーク→音声回復のP50/P95目標を機種別に凍結（暫定TBD） | 実機で各30回以上計測する提案 |
| NFR-PERF-03 | 電池・処理 | CPU・メモリ・バッテリー消費を画面OFF・Visualizer別・出力別に測定し閾値を決定 | Battery Historian / Perfetto等・現実的条件 |
| NFR-AUD-01 | 表示信頼性 | 元音源・要求値・OS申告・観測値・実測値・未知を分離し、未検証のBit-perfectを保証しない | 不一致値・非対応DACの検証 |
| NFR-AUD-02 | 忠実性 | 変換／DSP有効化の有無を正確に記録。Bit-perfectは対応経路での外部証拠に基づく | ループバック／DAC検証、テスト信号 |
| NFR-AUD-03 | 安全性 | 出力切替・再接続・プロファイル切替で危険な音量急増を回避する | 高感度機器で低音量から段階的評価 |
| NFR-AUD-04 | デジタル処理 | DSP経路のクリッピング防止と実装フィルター応答を検証。処理不能時は安全に停止／フォールバック | 全利得・最大入力信号・インパルス検査 |
| NFR-COMP-01 | 対応範囲 | minSdk=23を現状値とし、正式最低OS・対象ABI・DAP互換性を実機により確定 | 公開互換性マトリクス |
| NFR-COMP-02 | OS制約 | targetSdk・Foreground Service・ストレージ権限など公開時のAndroid要件を満たす | Play事前チェック＋自動検証 |
| NFR-SEC-01 | 最小権限 | 音源権限はSAF/MediaStore等の最小アクセス。不要な全ファイルアクセスを使わない | Manifest＋権限拒否テスト |
| NFR-SEC-02 | 秘密保護 | OAuth等のアクセストークンを暗号化・適切な有効期限で扱い、ログ・リポジトリ・同期外に漏らさない | 認証・ログ監査／依存診断 |
| NFR-SEC-03 | 通信 | サービス・同期通信はHTTPS/TLS、認証リダイレクト検証、リトライ・レート制御を行う | MITM耐性／失効／エラー試験 |
| NFR-PRIV-01 | 個人情報 | 履歴、再生習慣、機器情報は既定端末内保存。外部送信は目的と同意を分離する | データフローレビュー・パケット確認 |
| NFR-PRIV-02 | 本人制御 | 履歴削除、連携解除、アカウント退会、データエクスポート／消去を提供する | 退会・同期済みデータ削除試験 |
| NFR-PRIV-03 | 記録 | 診断ログは機微情報をマスキングし、送信前に表示・明示操作を要求する | ログ検査、送信同意検証 |
| NFR-LEGAL-01 | 権利 | サードパーティAPI、SDK、コーデック、画像、音源、GPL等の配布条件を遵守する | ライセンス台帳・法務チェック |
| NFR-LEGAL-02 | サービス規約 | DRM回避、許諾外ストリーム抽出、YouTubeからの音声分離再生等を公開版の前提にしない | プロバイダー別許諾ゲート |
| NFR-A11Y-01 | アクセシビリティ | TalkBack、文字サイズ拡大、色以外による区別、スクリーンの意味ラベルを実装 | Accessibility Scanner／実機操作 |
| NFR-UX-01 | UI品質 | 日本語を主要UI言語とし、多言語追加・プラットフォームサイズを考慮 | 画面スナップショット・可読性テスト |
| NFR-STORE-01 | 公開 | Google Play等の現在の対象API、Data safety、広告表示、プライバシー方針、署名、サポート要件を遵守 | リリースチェックリスト |
| NFR-OBS-01 | 診断性 | 標準的な診断ログとサポート向け環境情報を再現可能に取得できる | 問題再現レポート |
| NFR-MAINT-01 | 保守性 | 依存方向の単純化、疎結合、コードレビュー、静的検査、自動テストの実行 | PR/CIレビュー |
| NFR-TEST-01 | テスト | 要求ID→詳細設計→試験ID→結果→コミットを追跡可能にする | トレーサビリティ表 |
| NFR-TEST-02 | 品質ゲート | 重要機能のテスト・Lint・Debug／ReleaseビルドをCIで実施。実機音質試験は別途証跡を持つ | CI・端末テスト報告 |
| NFR-OPS-01 | 運用 | 外部API停止、認証障害、セキュリティ更新、問い合わせ、脆弱性報告窓口の運用手順を用意する | 障害訓練、連絡先検証 |

### Google Play対象APIに関する確認事項

Google Playの公式要件では**2026-08-31以降、新規Androidスマートフォン向けアプリ／更新のtarget APIは原則36以上**（例外類型あり）。2026-10-26時点で既存の `targetSdk=36` はこの点に適合するが、公開時点で再検証する。参照：<https://support.google.com/googleplay/android-developer/answer/11926878?hl=ja-jp>。

## 5. 外部サービス別実現可能性・提供条件

| サービス | 目標 | 現段階の設計上の扱い | 出荷ゲート |
|---|---|---|---|
| Qobuz | 高音質カタログ・再生 | `GATED`: 正規API／契約／契約上の高音質取得権限を確認 | 商用・公開アプリ向け利用許可＋認証検証 |
| Amazon Music | カタログ・再生／制御 | `GATED`: 承認制API／SDK可否未確定 | 適法な公開用実装手段を確保 |

| SoundCloud | カタログ・公式に許可されたトラック再生 | `GATED`: 再生可能形式・音源単位の規約を尊重 | APIキー・権限・利用条件 |
| YouTube / YouTube Music | 正規検索・連携・公式UIへの遷移 | `GATED`: 公式API規約は音声の分離やバックグラウンド再生に制限。`yt-dlp` による非許諾音声抽出は公開設計に採用しない | 正規の認可経路が成立した形態のみ |

**重要な公開ゲート**：正規連携が0件の場合、Audippを「ストリーミング統合製品」として一般公開しない。1件の場合は「対応サービス1件」と明記し、「複数サービス統合」という表現は用いない。2件以上かつキュー横断制御を検証できた場合に限り、機能制約を付して「複数サービス統合」と表現できる（提案、要承認）。

## 7. 非目標／禁止する誤表示

- 許諾のないストリーム取得、DRM回避、コーデック・SDKライセンス違反。
- サンプルレート表示だけでのBit-perfect断定。
- DSP処理と、同じPCMサンプルがDACまで無変更であるという保証の同時表示。
- 外部アプリが所有するPCMをAudippのDSP／Visualizerで処理したという表示。
- 未対応のストリーミング事業者／DAC／機種での動作保証。
- 端末固有オーディオ制御やアカウント登録を、一般的なローカル再生の必須条件にすること。

## 9. トレーサビリティ規約

- GitHub Issue・PRに少なくとも `FR-xxx` / `NFR-xxx` を記載し、関連する[詳細設計書](03_detailed_design.md)の `DD-xxx` と、`UAT-xx/TEST-xx` をリンクする。
