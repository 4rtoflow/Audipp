# Audipp — UI/UX Design System & Design Principles

> **Status:** Review Complete / Approved implementation baseline (2026-10-28)\
> **Version:** 1.0.0\
> **Updated:** 2026-10-28\
> **Scope:** Android smartphones and Android-based DAPs; initial PoC: local-file playback.  
> **Intent:** Design specification for human contributors and AI coding agents.

## 0. 位置付けと優先順位

この文書はAudippのビジュアル・インタラクション・画面構成・UI品質を規定する。機能そのものの採否、音声エンジンの詳細仕様、Android版以外の開発計画はPRD・機能要件・非機能要件を優先する。競合製品のUIは**参照**であり、画面や固有アセットを模倣・複製しない。

2026-10-27のレビュー修正では、利用者から委任された判断の範囲で、既存のテーマ3モード・ミニプレイヤー・モーション削減方針を要件定義FR-UI-03/06と詳細設計TEST-UI-01へ対応付けた。当時は本書全体の正式承認や実装完了を意味しなかった。2026-10-28の利用者指示により、本書を含む全レビューをCompleteとし、正式版1.0.0へ移行した。実装・実機検証は別に行う。承認・保留の記録は要件定義§9.1を正本とする。

**製品の二つの中心価値（同等の重要度）：**
1. 高品質な音声再生と、信号経路・再生状態の透明性。
2. 音楽に没入できる、美しく操作しやすい体験。

意匠のために音声再生の安定性・正確な情報表示・操作性を犠牲にしない。また機能の豊富さを理由に画面を情報で埋め尽くさない。

### Design statement

**Music first. Fidelity visible. Complexity on demand.**  
音楽を主役に、音質情報は確実に、専門的操作は必要なときに。構造で伝え、余計な言葉を増やさない。

2026-10-27のQ-01〜13回答により、日本語・英語UI、動画再生を持たない音声プレーヤー、無料・広告なしを確定した。YouTube系も動画UIへ置き換えない。Galaxy S25とFiiO M21を主要検証機とするが、幅広いAndroidスマートフォン・DAPの画面・操作へ適応する。Q-13のカスタムテーマ案は承認済みであり、利用者指定色をジャケット由来の色より優先する。

## 2. 守るべき原則（MUST）

1. **Content first:** 再生画面ではアルバムアート、曲名、アーティストを第一階層に置く。装飾は情報の可読性を妨げない。
2. **Self-explanatory UI / Show, don't tell:** 不要なセカンダリラベル、説明文、サブタイトル、見出し、装飾的マイクロコピーを追加しない。情報階層、配置、余白、タイポグラフィ、アイコン、状態変化で意味を伝える。個々のテキストには「これが無い場合、ユーザーが何を理解できなくなるか」の根拠を持つ。
3. **Theme choice is a user preference:** `System / Dark / Light` の3モードを提供する。初期値は `System`、ユーザーによる選択を永続化する。全画面・全状態・描画エフェクトを両配色に対応させる。
4. **Immediate control:** 再生・一時停止、次曲、現在位置の確認、シーク、キューへの移動は見つけやすく、明示的な操作で実行できる。主要ボタンをジェスチャーだけに依存させない。
5. **Progressive disclosure:** 日常操作を第一階層、再生モードと基本情報を第二階層、音声信号・デバイスの専門情報を第三階層とする。専門情報を隠蔽するのではなく、確実に到達できる位置に配置する。
6. **Fidelity of information:** 音源のフォーマット、デコーダ出力、実際の機器出力を混同しない。未取得値は「不明」「未対応」と表示し、推測値を確定情報として表示しない。
7. **Responsive / DAP friendly:** Androidスマートフォンと多様な画面サイズのDAPを第一級ターゲットとする。タップ領域、片手操作、横画面、ハードウェアボタンとの共存を考慮する。
8. **Performance by design:** 音声スレッド・再生安定性をUIより優先する。重いブラー、FFT、画像抽出処理は主スレッドと音声処理のホットパスから切り離す。
9. **Accessible by default:** テキストのコントラスト、十分なタッチサイズ、スクリーンリーダー、フォント拡大、モーション削減を守る。
10. **Distinct identity:** 競合アプリの画面をコピーせず、Audipp固有の情報階層、コンポーネント、余白、アニメーションを作る。

## 3. ビジュアルシステム

### 3.1 デザイントーン

- キーワード：**Immersive / Refined / Minimal / Expressive / Technical**。
- 再生体験はエディトリアル的で落ち着いた表現。無関係な装飾、過剰なグロー、ネオン、ガラス効果の多用を避ける。
- **初期テーマ設定は `System`**。Androidのライト/ダーク設定に追従する。`Dark` と `Light` をユーザーが明示選択した場合は、その指定を優先する。再起動後も保持する。
- 意図が自明な操作・領域を、英語の飾り見出し、補足文、件数表示で説明しない。「説明を削る」だけで理解が難しくなる場合は、まず配置・アイコン・情報階層を再設計する。
- アイコンは線幅と視覚重心を揃える。意味のない絵文字をUIアイコンとして用いない。
- 画面密度は「通常」と「情報重視」を将来的に選べる構成にする（初期PoCは通常を先行）。

### 3.2 Theme modes / セマンティックカラー

**テーマ設定は3モードで必須（MUST）。** `System`（デバイスの設定に合わせる）を初期値とし、`Dark` / `Light` はユーザーによる固定指定とする。テーマはUIの外観だけを変更し、再生位置、キュー、再生状態、可視化プリセット、画面の階層を変えない。

- `System`: Androidの現在のナイトモード（`uiMode` / `isSystemInDarkTheme()`等）に連動し、アプリ動作中の切り替えも反映する。
- `Dark` / `Light`: OS設定にかかわらず指定テーマを適用する。指定値をDataStore等で永続化する。
- `System`から固定モードへの変更および固定モード間の切り替えは**即時反映**。再生セッションを作り直さず、音を途切れさせない。
- `System`を選択しているときだけOSモードの変更に追従する。バッテリーセーバーなどがOS側の実効テーマへ影響する場合は**OSから報告される実効モード**を適用する。
- すべてのコンポーネントはテーマに依存しないセマンティックトークンを参照し、画面内の固定色を原則禁止する。Androidシステムバー/ナビゲーションバーのアイコン明度も実効テーマに合わせる。
- テーマ選択UIは **設定 → 外観 → テーマ** に置く。選択肢は「デバイスの設定に合わせる」「ダーク」「ライト」。選択状態を色だけに頼らず識別できるようにする。

初期の提案トークン（ブランド確定値ではない）：

| Semantic token | Dark | Light | Intended use |
|---|---|---|---|
| `color.bg.base` | `#0B0D12` | `#F7F8FA` | アプリ背景 |
| `color.bg.surface` | `#171A21` | `#FFFFFF` | カード・ツールバー |
| `color.bg.elevated` | `#242833` | `#ECEFF3` | 浮遊UI・選択背景 |
| `color.text.primary` | `#F7F8FA` | `#161D28` | 主情報 |

**Artwork-aware palette:**
- ジャケットから色を抽出し、**両テーマでそれぞれ**適切な背景グラデーション／限定的なハイライトを生成する。ダーク用の濃いオーバーレイをライトへ反転流用しない。
- 主テキストと重要な操作アイコンは、ジャケット色に応じた無制限な変更をしない。既定のセマンティック前景色と安定した背景面でコントラストを保持する。
- 暗い・明るい・高彩度・モノクロ・アート無しを、**System(実効Dark/Light) / Dark / Light**それぞれで確認する。
- 切り替えアニメーションは控えめにし、`prefers-reduced-motion`相当のAndroid設定を尊重する。テーマ変化で明滅・過剰なブラーを生まない。
- OSの壁紙由来Dynamic Colorとジャケット由来Accentは別概念。両者を暗黙に混ぜない。

### 3.2.1 不要なラベルの削減基準（MUST）

- **残すべき要素：** 曲名・アーティスト、操作の理解に必要なラベル、曖昧なアイコンの識別情報、音質の意味や確度、失敗時の原因と復旧方法、初回導入に必要な案内。
- **削減候補：** 自明なセクションの重複見出し、説明がなくても分かるツールバーの英語小見出し、装飾的なタグライン、すべてのカードに繰り返す説明、結果件数の常時表示、重複するフォーマット表示。
- 視覚的ラベルを削除しても **TalkBack向け`contentDescription`、フォーカス、状態の通知は保持**する。視覚的ミニマリズムをアクセシビリティより優先しない。
- 操作が自明でない場合に「説明文を増やす」前に、配置やコントロール形状を検討する。**専門用語・エラー・未検証/デモ情報など誤解を招く場合は明示する**。
- AI実装時は表示文言を追加するたび、情報の役割を `必須 / 状態 / 補助 / 装飾` に分類し、`装飾` は削除、`補助` は削減・統合を検討する。

### 3.3 タイポグラフィ・余白・形状

- 文字サイズはsp、レイアウトはdpを基本とする（Android実装時）。OSの文字拡大設定を尊重する。
- 主タイトルは大きく、長い場合は折り返し・スクロール・省略規則を画面別に定義する。無条件の極小化を禁止。
- 本文・補助テキスト・技術値を明確に区別。サンプルレートやbit深度などは等幅数字を推奨。
- 基本スペーシング：`4 / 8 / 12 / 16 / 24 / 32dp` を候補とする。例外は理由を記録。
- 形状は極端な角丸の統一を避け、アートワーク・再生ボタン・カードで階層化する。
- 影を重ねるよりも、面の明度・境界・重なりで奥行きを表現する。

### 3.4 モーション

- 画面遷移は目的のある控えめな動きに限定。フェード、スライド、ミニプレイヤー→フルプレイヤーの連続性を優先。
- アニメーション時間の**暫定設計値**：短い状態変化 `120–180ms`、画面遷移 `220–320ms`。実機で検証し調整。
- 状態変化の完了をアニメーション終了まで不必要に待たせない。
- OSの「アニメーションを削除／低減」設定を尊重し、点滅・急激な色変化を避ける。
- 背景エフェクトを再生に同期させる場合も再生系から描画処理を分離する。

## 4. 情報アーキテクチャ（PoC）

### 4.1 トップレベル

**初期構成案（確定ではない）：**
- **ライブラリ**：ローカル音源、アルバム、アーティスト、楽曲、プレイリスト、最近聴いた曲。
- **検索**：インデックス化されたローカルライブラリから検索。
- **ビジュアライザー**：可視化プリセットへの入口。再生中画面からもアクセス可能。
- **設定**：トップバーなどからアクセス。トップレベルタブには含めない。
- **ミニプレイヤー**：再生中は対象画面にまたがって一貫して表示。ナビゲーション項目ではなく永続的な再生UI。

ローカル再生PoC段階ではストリーミング推薦やエディトリアルの架空コンテンツでホーム画面を埋めない。ライブラリの価値を優先し、外部サービス統合時に情報設計を再評価する。

基本設計のHome中心の画面図は完成版の案、本節はPoCの案である。両者の最終ナビゲーションは未確定だが、テーマ3モードと共通ミニプレイヤーは両段階で適用する。

2026-10-31：比較・全画面の状態遷移・戻り先・幅の候補は[#19のUIレビュー案](specifications/12_navigation_proposal.md)に記録した。Implementation Proposalであり、最終構成の承認や本書の承認済みベースライン変更を意味しない。

### 4.2 Now Playing（フルプレイヤー）

**基本階層（縦画面・標準密度）：**

1. 上部：戻る/縮小、現在の表示名、キュー・出力先・メニューへの到達。
2. 中央主役：大きな正方形のアートワーク。画面幅・縦高さに応じて自然に縮小し、操作部分を圧迫しない。
3. 曲情報：タイトル → アーティスト → アルバム（利用できる場合）。
4. 状態・音質：`FLAC · 24-bit · 96 kHz` 等の**ソース情報**と出力先名を区別して表示。タップで詳細へ。
5. シーク：進捗と経過/残り時間。操作可能なシークとロングコンテンツのアクセシビリティ。
6. 主操作：前へ／再生・停止／次へ。シャッフル・リピートは見つけやすい二次操作に配置。
7. セカンダリ：キュー、詳細情報、ビジュアライザー、歌詞（対応がある場合）への導線。

**タブレット・横画面・幅広DAP：** 可能な場合、アートワークと操作・詳細を横並びに再配置する。縦画面を横に伸ばしただけのレイアウトにしない。

### 4.3 ミニプレイヤー

- 常時一貫した位置・スタイル。画面下部のナビゲーションと干渉しない。
- 最低限：小さなアートワーク、曲名、アーティスト、再生/一時停止、タップでフルプレイヤーへ。
- 追加アクションは最大1つを初期値とし、後で設定可能な拡張スロットを設ける。
- 非再生時、初回起動時、音源が取り除かれたときの状態を明確にする。
- タップ領域が競合しないこと。音量・出力先操作は誤タップしにくい位置に置く。

### 4.4 キュー / 音楽情報

- 再生中の楽曲、次の楽曲、残りキューを区別する。
- ドラッグ並べ替え、曲の削除は視覚的なフィードバックと取り消し導線を検討。スワイプだけに依存しない。
- 音源詳細からアルバム・アーティストへ移動できる。
- 再生画面の二次セクションで、利用可能なメタデータやクレジットを探索できる。実データ未取得時には空欄・架空値を表示しない。

## 5. Audiophile UX — 信号の透明性

音源側・再生エンジン側・出力経路側の情報をUIレベルで分離する。

| レイヤー | 表示例（値はサンプル） | 注意点 |
|---|---|---|
| **Source / File** | FLAC, 24-bit, 96 kHz, Stereo | ファイルの実メタデータに由来。音源の品質を示すのであってDACへの実出力を保証しない |
| **Decoder / Engine** | PCM, 32-bit float, 96 kHz | エンジンから値が取得できる場合に限る |
| **DSP / Processing** | EQ On, ReplayGain Off | 変換有無・処理経路を明確にする |
| **Android Output Route** | USB Audio / Built-in / Bluetooth | OSから判別できる範囲に限定 |
| **Device / DAC** | Device name, supported or negotiated format | 対応形式と実際の転送形式を区別する。機器の内部処理は原則推定しない |
| **Bit-perfect status** | Verified / Not verified / Not supported | 信頼できる検証手段がない限りVerifiedにしない |

**UIルール：**
- 情報の確度を `Confirmed / Reported by OS / Estimated / Unknown / Unsupported` 等で扱えるデータモデルにする。ラベルは日本語で表示。
- メイン画面では重要な1〜2要素に絞り、全情報を **Signal Path / Audio Details** シートで提示する。
- Hi-Res、Lossless、Bit-perfectのバッジは意味と成立条件を明文化する。「ハイレゾ音源」は「ハイレゾ出力」を意味しない。
- USB DAC切断、Bluetoothへの切替、サンプルレート変更に追従して画面を更新する。
- 取得不能なデバイス情報を機種名やメタデータから推測して断言しない。

## 6. Visualizer — 音の可視化

**推奨プリセット：** Waveform / Spectrum / VU Meter / Stereo Vectorscope / Ambient Motion。初期PoCでどこまで作るかは機能優先度に従う。

- **Now Playingの補助表示**と**没入型フルスクリーン**の2モードを想定する。可視化キャンバス、グリッド、針、凡例は各テーマに合わせたコントラストにする。
- 各プリセットは共通の再生状態・テーマ・音声データインターフェースを使う。
- 静的シーク用波形（事前解析）とリアルタイム波形（PCMベース）を区別する。
- VUメーターは計測方式（RMS/peak、dBFSなど）を説明できる仕様にする。視覚的な針だけなら実測値として誤認させない。
- ステレオベクトルスコープは左右独立の信号を必要とする。モノラル信号では適切な状態を表示する。
- FFTの周波数分解能、窓関数、更新頻度、平滑化、画面fpsを分けて扱う。見た目のための補間を測定精度と混同しない。
- 音声が利用できないときは**停止・未対応・無音**を区別し、偽のビジュアライザーを動かさない。
- プリセットの重い処理は画面が非表示なら止める。熱・電力・フレーム落ちを実機で測定する。
- Android標準の `android.media.audiofx.Visualizer` は低品質の部分的な音声データを提供するAPIであり、高精度な信号解析の代替にはならない。採用時には権限・音源経路・制限を個別に検証する。

## 7. インタラクションと状態の設計

すべての主要画面で以下の状態を個別に設計する。

- `Initial / Empty`: 音源がない。ローカルファイル追加方法を示す。架空のアルバムで埋めない。
- `Scanning / Loading`: ローカルライブラリの読み込み・スキャン中。進捗が取得できない場合は偽の%を表示しない。
- `Ready / Playing / Paused`: 再生操作、曲情報、進捗の整合性。
- `Buffering / Seeking`: 実際の状態に応じたフィードバック。ローカル再生でも読み込み遅延に対応。
- `Error / Permission denied / File missing`: 原因が分かる範囲で説明し、再試行・再設定の導線を設ける。
- `Output changed / Device disconnected`: 出力切替時の状態、必要なら警告・継続再生の挙動を明示。
- `Missing artwork / Unknown metadata`: 一貫したプレースホルダー。読めない薄色テキストは禁止。

ジェスチャーは操作の高速化には使えるが、発見可能な代替ボタンを持たせる。破壊的操作は取り消し可能にするか適切な確認を設ける。

## 8. アクセシビリティ・アダプティブUI

- タッチ対象は原則**最低48×48dp**。ビジュアルアイコンが小さくても操作領域は確保する。
- **WCAG 2.2 AA**を参照し、通常テキストは4.5:1以上、大きなテキストと重要なUIの非テキスト要素は3:1以上のコントラストを目標とする。
- テキスト拡大時に曲名、コントロール、時刻が重ならず、必要に応じてスクロール・折り返しする。
- TalkBackでボタンの意味・現在の再生状態・選択状態が読み上げられる。単なる「ボタン」や「アイコン」というラベルは付けない。
- 色だけでロスレス状態、エラー、アクティブ状態を表現しない。
- 幅の狭いDAP、通常のスマートフォン、大きなAndroid端末、横画面、マルチウィンドウをテスト対象にする。
- AndroidをJetpack Composeで実装する場合、NavigationBar/NavigationRailとMaterial 3 Adaptiveを参考にする。ただし既存実装の技術選択を本書だけで上書きしない。
- Dark / Light の双方で、通常・無効・選択・フォーカス状態のコントラスト、システムバーのアイコン色、画面遷移とボトムシートの配色を検証する。

## 9. デザイントークン / Component API

最低限、以下を共通UIコンポーネントに切り出す（名称は概念名）。

```text
AudippTheme
  ├─ ThemeMode (System / Dark / Light) / ThemePreferenceStore
  ├─ SemanticColors / ArtworkPalette
  ├─ Typography / Spacing / Shapes / Motion
  ├─ TrackArtwork
  ├─ TrackTitleBlock
  ├─ AudioQualityChip      # sourceとoutputを混同しない
  ├─ PlaybackControls
  ├─ SeekBar / WaveformSeekBar
  ├─ PersistentMiniPlayer
  ├─ AudioSignalDetailsSheet
  ├─ OutputDevicePicker
  ├─ QueueTrackRow
  └─ VisualizerSurface
```

- コンポーネントはプレゼンテーションと再生エンジンの状態取得を分離する。
- デザイン値はトークンを参照。マジックナンバーの追加には根拠を記録する。
- 再生の状態は単一の信頼できる状態管理層を参照し、ミニプレイヤーとフルプレイヤーで食い違わせない。
- 日本語・英語・長いアーティスト名・右から左の言語拡張にも配慮した文字列レイアウトを用いる。

## 10. 品質ゲート / Acceptance criteria

### ユーザー体験

- [ ] 初回起動でローカル音源が無い場合、追加方法を確認できる。
- [ ] ライブラリから楽曲を選択して再生し、再生画面に遷移できる。
- [ ] 再生画面以外でもミニプレイヤーから一時停止・再開できる。
- [ ] 曲名・アートワーク・シーク位置がミニプレイヤー/フルプレイヤー/システム通知と矛盾しない。
- [ ] ライブラリへ戻っても再生操作が途切れない。
- [ ] ファイル形式・ビット深度・サンプルレートの取得値の**意味と由来**が正しい。
- [ ] USB DAC切断等で出力先情報が更新され、誤った「bit-perfect」表示が出ない。
- [ ] アート無し・暗色/明色のアート・超長いタイトルで視認性を保つ。
- [ ] ジェスチャーを使わずキュー・シーク・情報詳細へ到達できる。
- [ ] 設定で `System / Dark / Light` を切り替えられ、選択が再起動後も残る。
- [ ] `System` はOSの実効テーマ変更に追従し、固定選択はOS変更に影響されない。
- [ ] テーマ切替中も再生状態・再生位置・再生キュー・画面状態が保たれる。
- [ ] ライブラリ、Now Playing、検索、Visualizer、設定、詳細シートの不要なラベルと説明を削減し、残した文言に機能上の根拠がある。

### 品質・性能

- [ ] 画面遷移・スクロール・シーク中のジャンクを実機計測する。ベンチマーク基準値は対象端末とPoC実測後に決定する。
- [ ] ビジュアライザーOFFで音声解析に伴う継続的なCPU負荷が残らないことを確認する。
- [ ] 大きなライブラリのスクロールとサムネイル読み込みでUIスレッドが詰まらない。
- [ ] 高負荷時でも音声再生を優先し、可視化品質を段階的に下げる。
- [ ] 最低48dpの操作領域、TalkBack、文字サイズ拡大、コントラストを検証する。
- [ ] スクリーンショットによるVisual Regression Test（ゴールデン画像差分）を主要状態ごとに実施する。
- [ ] **Dark / Lightの2配色 × 通常 / 空 / エラー / モーダル / 可視化等の主要状態**を検証する。SystemモードのOS追従を別途テストする。
- [ ] ライトテーマのジャケット連動背景、ミニプレイヤー、ナビゲーション、音質シートで文字/アイコンが視認できる。

## 11. AI coding agents向け実装規約

**Before coding**
1. `design.md`、PRD、対象画面の機能要件・既存実装を確認する。PRDが未確認なら暗黙の仕様を発明しない。
2. 変更がデザイン原則に触れる場合は、画面・コンポーネント・トークン・状態のどれが変わるかを説明する。
3. UIの新規追加前に共通コンポーネントと既存トークンが再利用可能か確認する。
4. 追加予定の表示テキストについて、必要性・重複・視覚的構造での代替可能性を検討する。

**During coding**
1. 画面単位の直接色指定、任意の余白、重複する再生状態管理を追加しない。
2. 無根拠なビジュアル・アニメーションを実装しない。美しさと操作性が衝突した場合は両立案を提示する。
3. 音源・出力・DACの情報を推測で埋めない。UIで未知の値を表現可能にする。
4. ライブラリ・再生・キュー・音質詳細・可視化の責務を分ける。
5. 権限が必要な処理、CPU負荷が高い処理、音声信号を扱う処理は再生の安全性を先に検証する。
6. 新しいUIライブラリ、アセット、ブランド的外観、ナビゲーション構造の変更は理由とトレードオフを記録する。
7. 表示上の装飾的ラベルや二重説明を新設しない。文字が必要な箇所に限定する。スクリーンリーダー向け非表示ラベルは削らない。
8. `ThemeMode` と実効配色を分離する。新規コンポーネントにはDark/Light両テーマのトークンを適用し、`System`/明示選択の切替後も状態を保持する。

**Before PR / completion**
1. 変更画面の通常/空/読み込み/エラー状態を提示する。
2. スクリーンショット（可能なら実機）と差分、長いテキスト・アート無しの動作を提示する。
3. PRD、デザイントークン、アクセシビリティ、音声メタデータの正確性に対する自己評価を添える。
4. 未実装項目や検証できていない機器・信号フォーマットを明示する。
5. 実装と本書が矛盾する場合、黙って本書を書き換えず人間のレビューに回す。
6. ラベル削減前後の画像比較、およびDark/Light双方の画面キャプチャを提出する。SystemのOS追従と設定永続化も検証結果を添える。
